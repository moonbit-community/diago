## Description
Diago currently depends on `dowdiness/js_engine` to execute the embedded D2 Rough.js sketch runtime and MathJax LaTeX runtime. The long-term goal is to remove this JavaScript parser and interpreter dependency once the MoonBit community provides mature, reusable sketch and LaTeX implementations.

This work is intentionally deferred. Diago should not develop replacement sketch or LaTeX engines solely to remove `js_engine` while suitable community implementations are unavailable.

## Design
Periodically evaluate community implementations as possible replacements. A replacement must preserve Diago's public rendering behavior, support native, JavaScript, and WebAssembly targets, and retain normalized SVG parity with D2 for both Dagre and ELK layouts.

Once suitable implementations exist, replace the two internal interpreter-backed adapters independently, remove the embedded JavaScript runtimes, and finally remove `dowdiness/js_engine` from the module and package dependencies.

## Acceptance Criteria
- [ ] A community sketch implementation can replace the embedded D2 Rough.js runtime while preserving the normalized D2 sketch SVG corpus on all supported targets.
- [ ] A community LaTeX implementation can replace the embedded MathJax runtime while preserving D2-compatible SVG output and text metrics on all supported targets.
- [ ] Diago's Dagre and ELK example parity tests pass after both replacements.
- [ ] Native, JavaScript, and WebAssembly builds and tests pass without `dowdiness/js_engine`.
- [ ] The `dowdiness/js_engine` module dependency, package imports, embedded JavaScript assets, and associated host runtime requirements are removed.
