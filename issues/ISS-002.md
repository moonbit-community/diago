## Destination

A decision-complete design for a publishable Node.js 20+ ESM npm package under
`markdown/`. The package ships a version-matched Diago Wasm binary and provides
markdown-it, remark, and VitePress adapters that replace exact `diago` fences
with inline SVG while preserving failed fences and returning diagnostics.

## Notes

- Planning only: this map ends when implementation can be specified without
  unresolved product or architecture decisions.
- Use `wayfinder`, `domain-modeling`, `research`, and `prototype` as indicated
  by each child ticket.
- Consult `CONTEXT.md` for canonical terms and
  `docs/markdown-package-design.md` for the final design authority.
- A Diago fence carries no plugin-specific info-string options and is supported
  at every valid CommonMark nesting depth.
- Successful fence tokens/nodes become inline SVG. Failed tokens/nodes are
  delegated without mutation and produce structured diagnostics without
  preventing successful fences from rendering.
- The package is build-time Node.js ESM, not a browser runtime integration.
- 2026-07-20: Implemented the package under `markdown/` with the root renderer,

- 2026-07-20: Final validation covered Node host adapters, the 171/12/4 Wasm
  corpus classification, byte-identical packaged-Wasm/native Dagre and ELK
  output, and the repository's strict 183/183 D2 parity for both engines.

## Decisions so far

- [Define bundled Wasm loading and npm layout](ISS-005.md) — publish one
  Node.js 20+ ESM package with one private, version-matched Wasm artifact;
  adapters share a cached default renderer and an explicit factory remains
  available for isolation.
- [Define the inline SVG trust boundary](ISS-009.md) — the first release is
  limited to trusted project-authored Markdown because generated inline SVG is
  active content and Diago Markdown labels can contain raw XHTML.
- [Define the shared JavaScript adapter contract](ISS-003.md) — one shared fence
  compiler owns identity, Wasm requests, results, and diagnostics behind a
  small renderer and adapter option interface.
- [Choose deterministic SVG namespace identity](ISS-004.md) — derive a stable
  block ID from document ID, diagram digest, and identical-source occurrence,
  then pass it through Diago's native salt option.
- [Define CommonMark source transformation semantics](ISS-006.md) — operate on
  parsed fence tokens/nodes rather than rewriting Markdown source; delegate
  failed nodes unchanged.
- [Define structured diagnostics and host propagation](ISS-007.md) — use one
  error model and host-native storage while allowing callbacks to enforce a
  failing build.
- [Decide import behavior inside Diago fences](ISS-008.md) — do not perform
  filesystem or network resolution; imports remain fences with `DIAGO_IR`.
- [Specify markdown-it, remark, and VitePress adapter contracts](ISS-010.md) —
  provide one default export per host over the same fence compiler.
- [Define npm release and compatibility policy](ISS-011.md) — publish `diago`
  in lockstep with the MoonBit version and bundle exactly one private Wasm.
- [Define the Markdown integration acceptance gates](ISS-012.md) — require the
  171/12/4 official-corpus classification, cross-host behavior parity, package
  inspection, and clean-consumer tests.

## Out of scope

- External SVG assets, browser-time placeholders, and pluggable embedding
  policies; this effort supports inline SVG only.
- Browser runtime, UMD/IIFE bundles, and generic Vite plugins.
- New MoonBit Markdown APIs, native CLI commands, or Wasm ABI changes.
- Implementing the package; execution begins only after this map reaches its
  destination.
